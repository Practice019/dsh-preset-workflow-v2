# 改工作流规则的指南（给 AI 用）

> 这份文件就是「工作流注入」页签里那份指南。人和 AI 读的是同一份，不要另抄一份。

## 你只会改一个文件

```
evolve/ledger.md          ← 规则账本（唯一写入目标）
```

**不要动** `workflow.md` 的 `<!-- L1:BEGIN -->` / `<!-- L1:END -->` 之间的骨架——
那是流程本身（七阶段 + 铁律）。用户明确要求改流程时才动它，并且要说清改了什么。

## 三条硬约束（违反即返工）

| # | 约束 | 违反的后果 |
|---|---|---|
| 1 | **单条正文 ≤ 60 字符** | `evolve_add` 会直接拒收；界面上保存也会被拒 |
| 2 | **只增/删/改单条**，禁止整篇重写 ledger | 丢失人工痕迹与 `hits` 历史，且容易把标记写坏 |
| 3 | 标记 `<!-- LEDGER:BEGIN -->` 与 `<!-- LEDGER:END -->` 各**必须保留一个** | 编译期找不到标记 → 规则**全部不注入**（只剩骨架），日志会提醒 |

另外：`id` 稳定——新增用「已有最大编号 + 1」（现有最大 `E018` → 新条 `E019`），不要复用已删的 id。

## 三种改法（按优先级）

### 1) 加一条 → 用 `evolve_add`

```
evolve_add(scope, when, text)
  scope: always 或 P0..P6
  when : 什么时候该想起这条（命中条件）
  text : 规则正文，≤60 字符
```

它自动去重（相似则 `hits++`）、自动分配 id、自动 trim。

**正文写不下 60 字符时**：先用 `write` 把全文写进 `evolve/lessons/E0xx.md`，
再提交一行**索引**（≤60 字符）：

```
- [E0xx | always | 命中条件] 一句话结论 → lessons/E0xx.md
```

### 2) 改一条 → 读那一行，只替换那一行

保留行尾元数据 `(added: YYYY-MM-DD, hits: N)`，不要改它的历史。

### 3) 删一条 → 删掉那一整行

连行尾换行一起删，**不要留下空行或孤立的标记**。删除是有损操作：如果这条规则还有价值，
先把它折进 `workflow.md` 骨架或 `workflow-phases` 技能，再删。

## 改完怎么生效

账本只是**源文件**；常驻段在**会话挂载时**才编译。所以：

```
改源文件  →  开新会话（或重启 dsh，更稳）  →  新会话的系统提示里出现新的
            [WF-v2.4 | compiled E0xx | N 条活跃]
```

**本会话内不会生效**——不要以为改完当前会话就变了。

## 验证清单（改完自检）

1. `ledger.md` 里 `BEGIN` / `END` 各一个？条目数对不对？
2. 新/改的正文是否 ≤60 字符？
3. 用「工作流注入」页签刷新一次：编译头里的 `compiled E0xx` 与 `N 条活跃` 是否如预期？
4. 开新会话，系统提示里搜 `WF-v2.4` 确认它真的进去了。

## 常见错误

| 症状 | 原因 |
|---|---|
| `{"ok":false,"action":"rejected-too-long"}` | 正文超 60 字符（改走 lessons 索引行） |
| 新会话里规则全没了、只剩骨架 | 标记写坏了，或整文件被重写 |
| 日志有「软阈值」提醒 | 总长超 2000 字符（不阻断，但该把长条目下沉到 `lessons/`） |
| 改了没反应 | 还在旧会话里；挂载时才编译 |
