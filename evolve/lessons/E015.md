# E015 · 引用外部输出字段前先实测其语义

**作用域**：always
**命中条件**：解析或汇总第三方程序 / API / 命令输出，并把结论报告给用户之前
**原添加日期**：2026-09-27
**原 hits**：0

## 正文

引用外部程序输出的字段时，**必须实测该字段的语义与覆盖度**，不得因字段名眼熟就按其字面意思解释。

要实测的四项：

| 项 | 问什么 |
|---|---|
| **来源** | 这个值是谁算的？是实测值还是自报值？ |
| **是否实测值** | 是现场读出来的，还是根据别的数据推算的？ |
| **缺失率** | 有多少条记录没有这个字段？ |
| **是否会重复计数** | 一个实体会不会被算两次？ |
| **标记字段的真实判据** | 这个 `is_xxx` 实际是按什么条件置位的？ |

**把结论说出去之前，先做那个最便宜的验证实验。**

## 两个典型翻车

### ① `EstimatedSizeKb` 当真实磁盘占用

`EstimatedSizeKb` 是**安装器自报值**，不是实测占用。
按它求和会**系统性低估或高估**，且不同安装器的估计口径不同，加总没有意义。

### ② `is_orphaned` 按字面理解

字面看像「注册表残留」，**实际语义是「未注册的便携安装」**。
按字面理解会把**正常可用的便携程序**报成垃圾。

## 落地

1. 拿到字段名后，**先找它的定义处**（文档 / 源码 / 实测）
2. 若找不到定义 → 做一个**最便宜的判别实验**（造一条已知情况的记录，看该字段取值）
3. 把实验写下来，作为后续解释该字段的依据
