# E013 · 包装外部程序：成功判据用产出物，不用退出码

**作用域**：always
**命中条件**：给任何外部 exe / CLI / 第三方程序做 subprocess 包装或自动化时
**原添加日期**：2026-09-27
**原 hits**：0

## 正文

包装外部可执行文件时，**成功判据一律以「产出物」为准**（文件存在、非空、可解析），
**绝不使用子进程 `returncode == 0`**。

动手前**先实测该程序的退出码语义**，并把该实测**写成回归测试**。

## 为什么

**很多 GUI 程序失败时也返回 0。**

这不是边缘情况 —— GUI 程序常常是「启动一个窗口然后返回」，退出码反映的是
「窗口是否成功创建」，而不是「用户的操作是否成功」。批处理模式下如果程序内部吞掉异常、
只弹个框就退出，退出码同样是 0。

以退出码为判据的代码会**静默地把失败当成功**，然后把损坏或缺失的产出物传给下游。

## 落地

```js
// ❌ 错
const r = spawnSync(tool, args)
if (r.status === 0) ok()

// ✅ 对
const r = spawnSync(tool, args)
const out = path.join(outDir, 'expected.ext')
const ok = fs.existsSync(out) && fs.statSync(out).size > 0
if (!ok) throw new Error(`${tool} 退出码 ${r.status}，但产出物缺失/为空`)
```

## 动手前必做的实测

1. 故意让它失败一次（给个非法输入），**看退出码是多少**
2. 记录这个数字 —— 如果失败也返回 0，那退出码在这条链路上完全不可用
3. 把步骤 1–2 写成回归测试，防止后续换了程序版本语义又变
