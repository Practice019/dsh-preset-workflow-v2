# E014 · 查找类函数必须无副作用

**作用域**：always
**命中条件**：实现自动发现、路径解析、配置回退等查找逻辑时
**原添加日期**：2026-09-27
**原 hits**：0

## 正文

查找 / 发现类函数（`discover` / `find` / `resolve` / `lookup`）**必须保持无副作用**：

- **不得**在内部写配置、缓存或任何持久状态
- 持久化要交给**上层命令**在**用户可见处**显式调用

## 为什么

否则**一次坏结果会被缓存，并污染后续所有运行**。

典型链条：

```
第一次运行（环境还没就绪）
  → discover() 找不到路径
  → 但它「顺手」把这次的结果写进了配置/缓存
  → 后续每次运行都读到这个坏结果
  → 即使环境早就就绪了，也永远发现不了
```

问题在于**坏结果被固化**，而且固化发生在用户看不见的地方 ——
用户看到的现象是「它就是不工作」，但没有任何线索指向那个缓存。

## 正确分工

| 谁 | 做什么 |
|---|---|
| `discover()` / `resolve()` | **只查、只返回**。不写任何东西 |
| 上层命令 | 拿到结果后，**决定**要不要持久化 |
| 持久化动作 | 在用户可见处显式执行（如 `xxx init` 命令打印出「已写入 <路径>」） |

## 自检

写完查找函数后问：「如果这次返回的是错的，会不会有东西被写下来？」 —— 如果会，就是副作用。
