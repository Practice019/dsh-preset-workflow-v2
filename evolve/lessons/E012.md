# E012 · 诊断本机硬件故障时取两个独立数据源交叉验证

**作用域**：P3（实现阶段）
**命中条件**：诊断本机硬件故障（电池 / 磁盘 / 温度 / 风扇）
**原添加日期**：2026-09-27
**原 hits**：0

## 正文

**至少取两个独立数据源，交叉验证同一指标。**
两者在同一时刻**不一致，本身就是故障证据**。只看单一来源会漏判。

## 可用的数据源对

| 指标 | 源 A | 源 B |
|---|---|---|
| 电池 | `powercfg /batteryreport` 的即时行 | WMI `BatteryStatus` 直读 |
| 磁盘 | SMART 的 raw 值 | 厂商工具（如厂商的 SSD 工具箱） |
| 温度 | 系统传感器 / `Get-CimInstance` | BIOS / 厂商工具 |
| 风扇 | 系统传感器 | 厂商工具 |

## 为什么单一来源会漏判

单一来源的问题在于**它自己会撒谎**：

- 驱动层可能缓存旧值（`powercfg` 报告的容量可能是上一次充放电周期算出的估计值，不是此刻实测）
- 厂商工具可能对已知故障做「友好化」处理
- 某些字段是「安装器自报值」而非实测值（见 `E015.md`）

**两个源同时读**，不一致就说明至少有一个不可信 —— 这比「两个都看起来正常」有信息量得多。

## 落地

```powershell
# 示例：电池
powercfg /batteryreport /output "$env:TEMP\bat.html"
Get-CimInstance -ClassName Win32_Battery | Select-Object EstimatedChargeRemaining, BatteryStatus
# 两个数字在同一时刻应一致；不一致 → 记录为故障证据
```
